# 起動時APIキー・モデル設定仕様

## Purpose

固定モデルへの接続を起動時に確認し、必要な場合だけ先生提供のOpenRouter APIキーを入力して再接続する。

## Requirements

### Requirement: プロバイダとモデルを固定する

システムは、すべてのsakunyanセッションでOpenRouterをプロバイダとして使用し、モデル識別子を `deepseek/deepseek-v4-flash` に固定しなければならない。

プロバイダとモデル識別子の値は1つの設定箇所で管理し、起動処理と接続確認の両方がその設定を参照しなければならない。

#### Scenario: 固定モデル設定でセッションを開始する

- **WHEN** sakunyanがセッションを開始するとき
- **THEN** セッションはプロバイダ `openrouter` とモデル識別子 `deepseek/deepseek-v4-flash` を使用しなければならない

#### Scenario: 固定値を一元管理する

- **WHEN** 固定プロバイダまたはモデルを変更するとき
- **THEN** 変更対象は共通設定の1か所でなければならない
- **AND** 起動処理と接続確認は同じ設定値を使用しなければならない

#### Scenario: 生徒が別のモデルを選択できない

- **WHEN** 生徒が通常どおりsakunyanを使用するとき
- **THEN** 生徒にモデルやプロバイダの選択を求めてはならない
- **AND** セッションは固定されたプロバイダとモデルの設定を維持しなければならない

### Requirement: 起動時に接続を確認する

システムは、起動後かつ生徒の通常の質問を受け付ける前に、固定モデルから応答を取得できるか確認しなければならない。

#### Scenario: 固定モデルが応答する

- **WHEN** 起動時の接続確認でモデルから応答を受け取ったとき
- **THEN** sakunyanは接続確認OKと表示しなければならない
- **AND** 生徒の通常入力状態へ移行しなければならない
- **AND** APIキー設定の依頼を表示してはならない

#### Scenario: 固定モデルが応答しない

- **WHEN** 起動時の接続確認で、認証または接続の問題により応答を受け取れないとき
- **THEN** sakunyanは接続確認NGと表示しなければならない
- **AND** 先生からOpenRouterのAPIキーを受け取って入力するよう日本語で表示しなければならない
- **AND** sakunyanは自動的にAPIキー入力待ち状態へ移行しなければならない

### Requirement: 案内付きのAPIキー入力と再試行

システムは、専用の入力フローで先生から受け取ったOpenRouterのAPIキーを受け付け、入力後に固定モデルへの接続確認を再試行しなければならない。

#### Scenario: APIキー入力欄を表示する

- **WHEN** 生徒がAPIキー入力待ち状態になったとき
- **THEN** 入力欄を画面の中央に固定せず、左寄せの入力プロンプトを表示しなければならない
- **AND** 「🔑 ここにAPIキーを入力 👉」と、Enterで確定・Escで終了できる案内を表示しなければならない

#### Scenario: 生徒がAPIキーを送信する

- **WHEN** 生徒がAPIキー入力待ち状態でAPIキーを入力して送信したとき
- **THEN** sakunyanはそのキーをOpenRouterの実行時認証へ反映しなければならない
- **AND** `deepseek/deepseek-v4-flash` で接続確認を再試行しなければならない

#### Scenario: 送信したAPIキーが有効である

- **WHEN** 再試行でモデルから応答を受け取ったとき
- **THEN** sakunyanはAPIキー入力待ち状態を終了しなければならない
- **AND** モデルやプロバイダの選択を求めずに生徒の通常入力状態へ移行しなければならない
- **AND** APIキーをpi標準の認証ファイルへ保存しなければならない

#### Scenario: 保存済みのAPIキーで再起動する

- **WHEN** 有効なAPIキーを保存した後にsakunyanを再起動したとき
- **THEN** 保存済みのAPIキーを使って固定モデルの接続確認を行わなければならない
- **AND** APIキーの再入力を求めてはならない

#### Scenario: 送信したAPIキーが無効である

- **WHEN** 送信したAPIキーが無効または使用できないため再試行に失敗したとき
- **THEN** sakunyanはAPIキー入力待ち状態を維持しなければならない
- **AND** 先生から受け取ったキーを確認して再入力するよう日本語で表示しなければならない

#### Scenario: 生徒が設定をキャンセルする

- **WHEN** 生徒がAPIキー入力をキャンセルするか、明示的な終了操作を行ったとき
- **THEN** sakunyanは生徒の通常の質問を送信せずに終了しなければならない
- **AND** APIキーを表示してはならない

### Requirement: APIキーをログとエラーから守る

システムは、APIキーをログやエラーメッセージに含めてはならない。入力中のAPIキーは入力欄に表示してよい。

#### Scenario: 設定状態を表示する

- **WHEN** sakunyanが起動中、入力中、成功、失敗の状態を表示するとき
- **THEN** 状態表示には安全な案内と次に行う操作だけが含まれなければならない
- **AND** ログやエラーメッセージにAPIキーを含めてはならない
