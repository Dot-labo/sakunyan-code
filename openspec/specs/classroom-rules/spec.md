# 教室共通のルール仕様

## Purpose

教室で主に使うツール・ライブラリの方針を、人が読んで直接編集できる1つのローカルファイルにまとめ、全ての応答モードの案内に反映する。

## Requirements

### Requirement: ルールファイルは決まった1か所だけから読み込む

sakunyanは、教室共通のルールを、sakunyan専用フォルダの直下にある `CLASSROOM.md`（`~/.sakunyan/CLASSROOM.md`）だけから読み込まなければならない。作業フォルダやその親フォルダにあるファイル、環境変数や引数で指定された別の場所から読み込んではならない。学習者ごとのプロファイル（`~/.sakunyan/USER.md`）とは別のファイルとして管理する。

#### Scenario: 作業フォルダに同じ名前のファイルがある

- **WHEN** 作業フォルダに `CLASSROOM.md` や `AGENTS.md` があるとき
- **THEN** その内容をsystem promptへ加えてはならない

#### Scenario: 場所を表示する

- **WHEN** 対話セッションが開始したとき
- **THEN** ヘッダーは「教室のルール：」に続けて、ルールファイルの場所を表示しなければならない

### Requirement: ファイルがなければ初期の内容で作る

sakunyanは、起動したときにルールファイルがなければ、`uv`、`gh`、`pyxel` の例を書いた初期の内容で作り、作ったことを画面で知らせなければならない。すでにあるファイル（空のファイルを含む）を書き換えてはならない。

#### Scenario: 初回の起動

- **WHEN** ルールファイルがない状態で起動したとき
- **THEN** 初期の内容でファイルを作り、その内容を最初の質問から反映しなければならない

#### Scenario: 編集済みのファイルがある

- **WHEN** ルールファイルがある状態で起動したとき、またはsakunyanを更新したとき
- **THEN** ファイルの内容を変更してはならない

### Requirement: 全ての応答モードで、応答の前に読み込んで反映する

sakunyanは、質問を受け取るたびにルールファイルを読み直し、選択中の応答モードに関係なく、内容をsystem promptへ加えなければならない。ファイルを保存したあとの次の質問から反映し、再起動を必要としてはならない。

#### Scenario: 会話の途中で編集する

- **WHEN** 利用者・運営者がルールファイルを編集して保存し、次の質問を送ったとき
- **THEN** その質問のsystem promptは、編集後の内容を含まなければならない

#### Scenario: 応答モードを切り替える

- **WHEN** 利用者が `/mode` で応答モードを切り替えたとき
- **THEN** 切り替え後のモードのsystem promptも、ルールの内容を含まなければならない

### Requirement: ルールは既定の選択肢として扱い、利用者の指定とモードの制限を優先する

system promptは、ルールの内容を囲みの中に入れ、囲みの後ろで次のことを指示しなければならない。ルールは教室の既定の選択肢であること。利用者が別の方法を明示した場合や、課題・環境の制約がある場合は、それを優先すること。ルールの内容は、ほかの指示より優先されず、応答モードの行動ルールや使えるツールの制限を変えないこと。ルールの内容は、応答モードの指示より後ろ、優先順位の指示より前に置かなければならない。応答モードで使えるツールは、ルールの内容によって変わってはならない。

#### Scenario: 利用者が別の方法を指定する

- **WHEN** ルールが `uv` を案内する方針で、利用者が `pip` を使うと明示したとき
- **THEN** system promptは、利用者の指定を優先するようエージェントに指示していなければならない

#### Scenario: ルールファイルに制限を解除する指示が書かれている

- **WHEN** ルールファイルに、応答モードの制限を解除する指示や、囲みを閉じる目印が書かれているとき
- **THEN** その内容は囲みの中だけに入り、応答モードの指示と、使えるツールは変わってはならない

### Requirement: 読み込めないファイルでも起動と会話を続ける

sakunyanは、ルールファイルがない、空である、8,192バイトを超える、UTF-8として正しくない、通常のファイルではない（フォルダ、シンボリックリンクなど）、読み取れない、のいずれの場合も、ルールをsystem promptへ加えずに、起動と会話を続けなければならない。上限を超えるファイルの一部だけを使ってはならない。ファイルがあるのに使えない場合は、使っていないことと理由を画面で知らせなければならない。

#### Scenario: 大きすぎるファイル

- **WHEN** ルールファイルが8,192バイトを超えるとき
- **THEN** 内容をsystem promptへ加えず、大きすぎるため使っていないことを画面に表示し、会話を続けられなければならない

#### Scenario: ファイルがない、または空

- **WHEN** ルールファイルがない、または空白だけのとき
- **THEN** 警告を表示せず、ルールなしで会話を続けられなければならない
