## Context

sakunyanは`src/cli.ts`からpiへCLI引数を渡し、対象フォルダで対話セッションを開始する。現在はプロジェクトの拡張機能、Skills、プロンプトテンプレートを無効化しているが、`AGENTS.md`などのコンテキストファイルは読み込まれ、`.agents/skills`などがある未登録フォルダではpi標準の英語の信頼確認が表示される。また、許可ツールに`bash`が含まれるため、教育プロンプトで状態変更を禁止していても技術的な権限制御にはならない。

Issue #7では起動時の安全な既定値を扱う。Issue #4のモード選択基盤と、Issue #10の問題解決モードにおける広いコマンド実行権限は別変更とする。

## Goals / Non-Goals

**Goals:**

- 通常の`sakunyan <フォルダ>`起動を、プロジェクトを信頼しないアドバイスモードにする
- プロジェクト由来の設定、実行可能リソース、モデル向け指示を自動で取り込まない
- アドバイスモードでモデルが利用できるツールを読み取り専用の4種類へ限定する
- コマンドは子ども向けに説明し、本人が実行する対話方針へ揃える
- 子どもに不要な英語のプロジェクト信頼確認を表示しない
- 実際の安全境界をREADMEとテストに残す

**Non-Goals:**

- 問題解決モード、モード選択UI、危険操作の確認・禁止ポリシー
- OSレベルのサンドボックスやコンテナの導入
- `read`ツールの参照パスを作業フォルダ内へ強制する仕組み
- pi本体や依存パッケージへの変更
- APIキー入力画面やリンク表示の変更

## Decisions

1. **piの`--no-approve`を固定指定する。** プロジェクトを自動承認する`--approve`では確認画面を消せてもプロジェクト設定を有効化してしまう。`--no-approve`なら、安全側を維持したまま信頼確認を省略できる。
2. **`--no-context-files`を追加する。** 既存の`--no-extensions`、`--no-skills`、`--no-prompt-templates`だけでは`AGENTS.md`や`CLAUDE.md`を止められないため、コンテキストファイルも明示的に無効化する。この設定は将来の問題解決モードでも維持し、コマンド実行権限とプロジェクト由来の命令に対する信頼を分離する。
3. **安全に関わる固定引数は利用者引数より後に置く。** 利用者がCLIで`--approve`や別の`--tools`を渡しても、起動時にはsakunyanの安全な既定値が最終的に適用される並びにする。問題解決モードはCLI引数による迂回ではなく、Issue #10で定義した子ども本人の開始確認後に、セッション内で明示的に切り替える。
4. **起動時のツール許可リストを`read,grep,find,ls`へ縮小する。** アドバイスモードでは`bash`、`write`、`edit`を有効化せず、調査に必要なファイルの読み取り、検索、一覧表示だけを許可する。
5. **教育プロンプトを実際の権限へ合わせる。** 「調査用コマンドを実行してよい」という指示を削除し、コマンドが必要な場合は意味と手順を説明して子ども本人に実行してもらう。
6. **sakunyan組み込み拡張は維持する。** プロジェクト由来の拡張を無効にしても、コードから明示的に渡す`sakunyanExtension`はAPIキー設定と日本語UIに必要なため読み込む。
7. **最小の回帰テストで固定引数と教育方針を検証する。** piへ渡す引数列を決定的に確認できる形にし、信頼拒否、コンテキスト無効化、4ツール限定、コマンドを本人へ案内する方針が崩れたときに失敗するテストを追加する。piの対話UIを実際に起動する重いE2Eテストは追加しない。

## Risks / Trade-offs

- [アドバイスモードではシェルを使った調査ができなくなる] → `read`、`grep`、`find`、`ls`でコードを調べ、実行が必要なコマンドは意味と手順を子どもへ案内する。
- [リポジトリ固有の`AGENTS.md`やSkillsを利用できなくなる] → 両モードでプロジェクト由来の命令を自動読み込みしない。必要なファイルは通常の調査対象として明示的に読める。
- [`read`はOSサンドボックスではない] → READMEで読み取り支援ツールであることを明記し、強制的なパス隔離は本変更の対象外とする。
- [将来の問題解決モードとツール設定が競合する可能性がある] → 本変更は起動時の既定値だけを固定し、明示的なモード切り替え後の権限変更はIssue #10のSpecで定義する。
- [pi更新で引数の意味が変わる可能性がある] → piの固定バージョンと起動引数の回帰テストを維持する。

## Migration Plan

1. pi起動引数へ`--no-approve`と`--no-context-files`を追加し、安全関連の固定引数を利用者引数より後へ配置する。
2. 起動時のツール許可リストから`bash`を削除する。
3. 教育プロンプトを、コマンドを自動実行せず本人へ案内する内容へ変更する。
4. 起動引数と教育方針の回帰テストを追加し、既存テストと型チェックを実行する。
5. READMEをアドバイスモードの実動作へ合わせる。

問題が発生した場合は変更前の起動引数と教育プロンプトへ戻せる。保存データの移行は不要であり、既存の信頼記録も削除しない。
