## Context

`src/cli.ts` は pi を `read,grep,find,ls,bash` で起動する。`/mode` は `src/extension.ts` でプロンプトと表示を切り替えるだけで、ツール権限は変えない。固定している pi 0.84.2 は `--no-approve`、`--no-context-files` と拡張 API の `setActiveTools()` を備える。

## Goals / Non-Goals

**Goals:**

- 起動時とセッション開始時に読み取り用の四つのツールだけを有効にする。
- `/mode` で選択したモードのツール一覧を適用し、キャンセル時は権限を変えない。
- 未信頼プロジェクトの設定と指示ファイルを自動読み込みしない。
- Git とシェルの自動実行を現行モードから外し、表示と文書を一致させる。

**Non-Goals:**

- 問題解決モード、Git 専用ツール、任意コマンド実行の追加。
- OS レベルのサンドボックスや、読み取り用ツールによるプロジェクト外アクセスの完全な遮断。

## Decisions

### CLI とモードの両方で許可リストを設定する

CLI の `--tools` を `read,grep,find,ls` に変更する。モード定義には `tools` を置き、`session_start`・`/mode` 確定時に pi の `setActiveTools()` を適用する。初期値は CLI 側でも安全にして、拡張の初期化前にも `bash` が利用可能にならないようにする。現行の二つのモードは同じ四つを使う。単なるプロンプト上の禁止では実行権限を制限できないため採用しない。

### pi の既存オプションでプロジェクト由来の入力を止める

`--no-approve` と `--no-context-files` を固定指定し、既存の `--no-extensions`、`--no-skills`、`--no-prompt-templates` を維持する。pi の信頼確認を子どもに委ねず、`AGENTS.md` 等を自動でモデルへの指示に追加しない。

### Git を現行モードでは案内に限定する

pi に Git 専用の標準ツールはない。`bash` を Git の状態確認のためだけに許可すると、任意のシェル操作も許可される。現行モードでは Git コマンドの意味と実行手順を案内し、利用者が実行して共有した出力を説明する。将来、問題解決モードに Git の自動調査が必要なら、固定操作の専用ツールとして #10 で設計する。

## Risks / Trade-offs

- [既存の Git 自動調査やビルド実行ができなくなる] → 変更点を README に示し、利用者が実行した結果を読む流れへ変更する。
- [pi の読み取りツールは OS サンドボックスではない] → README に限界を明記する。パス制限が必要なら別途、各ツールとシンボリックリンクを含む検証を設計する。
- [モード追加時に広いツールが誤って有効になる] → モード定義を唯一の権限情報とし、起動・切り替え・セッション再開をテストする。

## Migration Plan

保存データの移行は不要。更新後の起動では読み取り用ツールのみが有効になる。Git とコマンドの調査結果は利用者が実行して貼り付ける。必要なら CLI とモード定義の許可リストを以前の値へ戻せる。

## Open Questions

なし。問題解決モードと Git 専用ツールの詳細は #10 で決める。
