## Context

sakunyanは、`@earendil-works/pi-coding-agent`を固定依存として起動するTypeScript製ランチャーである。ランチャーが対象フォルダへ移動し、piの標準UIにsakunyan専用の表示拡張と教育向けシステムプロンプトを追加する。macOSとWindows（Git Bash）を対象とし、pi本体のフォークや直接変更は行わない。

## Goals / Non-Goals

**Goals:**

- 現在実装済みの起動、UI、教育、ツール、セットアップ方針を再現可能な要求として残す
- pi更新時に、sakunyanが依存する境界と検証項目を明確にする
- 初心者向けの操作説明と、対象フォルダを明示する安全な起動経路を記録する

**Non-Goals:**

- 新しい機能やpi本体の改修
- APIキー発行サーバーやWeb検索の追加
- ファイル変更を技術的に完全禁止するサンドボックス
- 既存実装のアーカイブやコード変更

## Decisions

1. **ランチャーで対象フォルダを検証する**：`src/cli.ts`で引数を必須にし、解決したディレクトリへ`chdir`してからpiを起動する。対象範囲を利用者に意識させ、相対パスの誤解を減らす。
2. **pi本体はフォークしない**：表示と教育方針はCLI引数、専用拡張、システムプロンプトで追加する。pi標準の変更が必要な領域は標準表示を残す。
3. **プロジェクトリソースを抑制する**：`--no-extensions`、`--no-skills`、`--no-prompt-templates`を指定し、sakunyanの表示・教育設定を明示的なCLI拡張から読み込む。
4. **ツールはpiのallowlistで選ぶ**：`read,grep,find,ls,bash`を許可する。ファイル変更やGit操作を自動で行わない方針は教育プロンプトで示し、OSサンドボックスとは扱わない。
5. **メッセージをコードから分離する**：表示文は`src/messages.ts`、教育方針は`src/educational-prompt.ts`に集約する。

## Risks / Trade-offs

- [プロンプトは強制的な権限制御ではない] → piのツール制限と方針文を併用し、将来強い制御が必要になったら専用ツールやサンドボックスを検討する。
- [pi標準の英語メッセージを全て置き換えられない] → pi本体を変更せず、sakunyanが管理できる表示だけを日本語化する。
- [Git BashとPowerShellでパス表記が異なる] → Windows向けREADMEではGit Bashを前提にし、`/c/Users/...`形式を例示する。
- [固定piバージョンとNode要件の更新漏れ] → package.json、ロックファイル、ROADMAP、テストを同時に更新して検証する。

## Migration Plan

後付けの仕様化のみで、実行時の移行は不要。今後の変更では、関連するspecを更新してからコードとテストを変更する。仕様と実装が一致しない場合は、実装を先に変更せず差分を記録する。
