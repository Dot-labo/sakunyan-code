## なぜ必要か

生徒がAPIキーを入力するときに、入力先や設定内容で迷わず、先生から渡されたキーを安全に設定できる状態にする。起動後に固定モデルで疎通確認を行い、応答できない場合だけAPIキー入力へ誘導することで、初回設定を明確にする。

## 変更内容

- 起動後、固定プロバイダの固定モデルでモデルからの応答取得を確認する。
- 応答を取得できない場合、先生からAPIキーを受け取って入力するよう生徒に表示する。
- APIキー入力が必要になった時点で、自動的に入力待ちモードへ移行する。
- 入力されたAPIキーで再接続し、モデルから応答を取得できることを確認する。
- プロバイダを OpenRouter、モデル識別子を `deepseek/deepseek-v4-flash` に固定し、生徒がモデルやプロバイダを選択・変更できないようにする。
- プロバイダとモデル識別子を1か所で管理し、起動処理と接続確認から共通して参照する。
- 有効なAPIキーをpi標準の認証ファイルに保存し、再起動後も利用できるようにする。

## 機能

### 新しい機能

- `startup-api-key-model-setup`: 起動後のモデル疎通確認、APIキー入力依頼、入力待ちモードへの自動遷移、固定モデルでの再接続を扱う。

### 変更する既存機能

なし。

## 影響範囲

- 起動処理とログイン後の状態遷移に影響する。
- OpenRouterへのAPIクライアント設定、APIキーの入力・保持・再接続処理に影響する。
- 生徒向けの案内表示と入力待ちUIに影響する。
- 新しい外部依存関係は追加しない。
