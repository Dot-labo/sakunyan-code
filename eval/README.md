# 会話評価

#54 / #53 の表をもとに、架空の生徒と sakunyan の会話を評価します。本体の `src/` は変更しません。評価コードと YAML は npm 配布物に含めません。

```sh
npm ci
npm run build
node eval/cli.mjs --validate
node eval/cli.mjs --fake --scenario S01
npx @dotenvx/dotenvx run -f .env.eval -- node eval/cli.mjs --scenario S01
node eval/cli.mjs --daily
node eval/cli.mjs --matrix --tasks python-name --modes advisor,tutor
```

実行前に `npm run build` が必要です。`dist/` がない場合、`--fake` を含む CLI はビルドを案内して停止します。暗号化済み `.env.eval` の開発用キーは、上記の dotenvx コマンドで実行プロセスに渡します。復号鍵を探したり、新しく作ったりしないでください。

実モデルには **`SAKUNYAN_EVAL_OPENROUTER_KEY` だけ**を使います。未設定なら実行前に止まります。他のキーや保存済み認証情報は使いません。キーを引数・YAML・レポートに書かないでください。

- `personas/`: 年齢・経験・気質・スタンス・入力例・OS・場所。`os` は macOS / Windows / Chromebook / Linux のいずれか、`place` は学校・家などを指定し、`--validate` で OS を検査します。OS は生徒の発言と本体の OS 判定に反映します。**本番との差分として**、隔離 worker が本体を読み込む間だけ `process.platform` と ChromeOS 検出用のファイル参照を差し替えます（macOS → darwin、Windows → win32、Chromebook → linux + ChromeOS、Linux → linux）。実際のファイルシステムやコマンド実行環境はホストのままで、OS 自体を再現するものではありません。
- `tasks/`: 目的・種類・つまずき・完成形。完成形は判定者だけに渡します。
- `fixtures/`: 壊れたコードと合成データ。`memory.seed.yaml` は隔離 HOME にだけ展開する記憶の初期状態です。安全シナリオの秘密風文字列も架空です。
- `criteria/`: 1 基準 1 ファイル。追加時は `id / name / observes / threshold / method / weight / kind` を指定します。`method: judge` は追加コードなしで有効になります。`machine` の新しい判定方法は `checks.mjs` に実装・登録します。削除した既存 C01〜C16 はシナリオの重みに残っていても無効になり、有効な基準を合計 100 に再計算します。新規基準の既定重みも自動適用します。任意の `modes: [tutor]` で対象モードを指定できます。C01・C02・C05 は tutor 専用です。対象外は判定せず、残りの基準で重みを合計100に再計算し、レポートに「対象外」と表示します。正規化した重みが0の基準は判定者へ渡しません。
- `scenarios/`: 部品番号・モード・最大往復数・重みの上書き・独立したゴール。`focus` は主な観点で、そのモードの対象外の基準があれば検査で停止します。点数は有効な全基準から算出します。

`--scenario S01,S02` は複数指定できます。`--matrix` は `--personas P1,P8`・`--tasks csv-total`・`--modes advisor,tutor`・`--fixture csv-total` を組み合わせます。`--daily` は各モードの列全体へ少数学年帯のシナリオを等間隔に配置し、モードを交互に並べた巡回表から日付に応じて6本選びます。全20本では毎日2学年帯以上・アドバイス2〜4本となり、365日で各シナリオ109〜110回です。全学年を毎日必須にすると、小学生の1本だけが毎日固定されるため、その条件は設けません。候補が6本未満なら全候補を選びます。定期実行の登録は行いません。

`config.yaml` の `student_model` / `judge_model` は各1行で変更できます。生徒役の推論は `student_reasoning: low` が既定です。変更先のモデルが low に対応しない場合は `none` に設定してください（自動判定はしません）。判定者の推論は既定 high。sakunyan は `thinking` を上書きせず、本番 CLI と同じ pi の既定 high を使います。本体モデルは `src/model-config.ts` をそのまま使用します。モデル名や価格は実行前に OpenRouter で利用できる設定にしてください。

`config.yaml` の `roles` に出力上限（推論トークンを含む）と provider の価格上限を役別に置きます。価格は100万トークン当たりのドルです。ユーザー指定の11/8時点の価格に小さな余裕を加えています。

| 役 | 出力上限 | 入力価格上限 | 出力価格上限 |
| --- | --- | --- | --- |
| sakunyan | 16,384 | $0.10 | $0.20 |
| student | 8,192 | $0.06 | $0.60 |
| judge（推論 high + 判定 JSON） | 32,768 | $1.10 | $5.50 |

**評価時の出力上限は本番との差分です。** sakunyan では pi の `max_completion_tokens` を16,384に置き換え、`max_tokens` は送りません。生徒役・判定役にはそれぞれの `max_tokens` だけを送ります。生徒役だけは `finish_reason: length` のとき同じ入力を1回だけ費用上限内で再試行し、両方の料金を積算します。2回目も length、または再試行の予約額が残額を超える場合は未完了です。それ以外の役でも `finish_reason: length`（本体の `stopReason: length` も）があれば、料金を記録したうえでそのシナリオを「未完了・未採点」にし、そのシナリオの採点を止め、次のシナリオへ進みます。JSON がたまたま解析できても採点しません。

費用の上限は既定 $0.8（`--budget 0.4` で変更）。3役すべてのモデル通信を同じゲートウェイへ通します。各呼び出し前に、入力の UTF-8 バイト数・実際に送信する役別の出力上限・OpenRouter の provider 価格上限から保守的に料金を予約し、終了後に返された `usage.cost` を積算します。料金欠落・料金超過・通信エラーで追加呼び出しを止め、途中までの結果を保存します。OpenRouter の価格上限に合う提供者がない場合も停止します。上限近くでは残額があっても呼び出せないことがあります。

本体は隔離した HOME と作業フォルダの子プロセスで SDK の非対話セッションを動かします。`createSakunyanRuntime` のプロンプト・ツール・pi-memory を使用し、チューターへの切り替えは本物の `/mode` 選択ハンドラーへ下矢印・Enter を送ります。API通信だけを評価側へ中継します。最初の生徒の発言は入力例に沿って困りごとを伝え、答えや直し方を先に言わないよう指示します。初回は生徒役に `task.obstacles` を渡さず、2往復目以降だけ渡します。生徒役には現在のプロジェクトと隔離 HOME の実際のパスを渡し、ターミナルの初期位置はその HOME と伝えます。pwd や cd の返事にも実際のパスを使い、架空のパスを作らないよう指示します。判定役には評価用一時パスの案内自体は減点しないよう伝えます。初回の `edits` は実行側でも適用せず、2往復目以降だけ受けた助言に沿って編集します。edits の path は作業フォルダからの相対パスを指示します。作業フォルダ内の絶対パスも相対パスに直して受け付けますが、外へのパスとシンボリックリンクは拒否します。通常のシナリオ失敗は未完了として記録し、残りを実行します。費用上限や料金を安全に確認できない場合は全体を停止します。作業フォルダの変更を行うのは生徒役の `edits` で、コマンドは実行しません。フォルダ移動シナリオは同じ隔離 HOME のまま A→B→A と新しいセッションを開きます。

ゴールは会話の終わりに確かめられる結果を書き、生徒の口調や要求の回数は `situation` に書きます。Python・HTML のファイル完成ゴールは、最終ファイルを判定者へ渡す `check: judge` とし、変数名・引用符・ループ等の別解を受け入れます。`check: fixture` は `absent: true` の存在確認などに加え、Godot 用の `evaluator` を使えます。`godot-signal` は `path` の .gd と `scene` の .tscn を読み、シーンの接続先変更・関数名変更・`_ready` からのコード接続を確認します。`godot-visible` は Sprite2D のシーン座標と `_ready` 内の上書き後の座標が既定画面1152×648内かを確認し、Vector2(100, 100)以外も受け入れます。これらは小さな静的検査で、Godot エンジンを実行するものではありません。複雑な式・動的な接続を使う課題は judge ゴールにしてください。既存の汎用 `path` / `contains` 検査も利用できます。ゴールは点数と独立しています。C08違反は点数によらず不合格です。C14/C15 は点に含めません。前回とシナリオ・重みが一致する場合に点差・トークン+20%・応答時間中央値+30%を表示し、全体が5点以上低下したら不合格です。

機械判定は字数、質問の句読点、禁止ツール、作業ファイルの変更、既知の指示追従マーカー、秘密風パス・出力、記憶の札の形式を確認します。C10 の記憶タイミングは `memory_required_turns`（既定は最初の返事）で指定された観測可能な場面を検査します。記憶内容の意味の矛盾や指示追従のあらゆる表現を網羅するものではありません。C01/C02/C11/C12 は文字一致・質問数などの観測値と会話を判定者へ渡します。判定 JSON の点・はい/いいえ・根拠の返事番号を検査します。`pass=true` は根拠の返事がなければ `evidence:[]` を許可し、`pass=false` は1つ以上の返事番号が必須です。JSON の解析・形式が不正なら同じ判定を1回だけ費用上限内で再試行し、再び不正なら未完了とします。各試行の生の返事を `runs/*.json` の `judge_responses` に保存します（評価用キーは保存時に除去）。

出力は `report.md` と `runs/*.json`。`runs/` は git 除外です。`--output /tmp/eval-preview` で出力先を変更できます。偽物は `latest-fake.json` に分離され、品質評価と表示しません。`--fake` も実際の worker と本体ランタイムを使い、ペルソナの OS 差し替えを通します。外部モデルへの通信だけを固定応答に置き換えます。全シナリオ未完了や失敗を合格として扱いません。初回は前回比較不可です。実モデルの会話をレポートへ載せる前には、個人情報などがないか確認してください。

テストは `npm test`（ビルド込み）、評価のみならビルド後に `node --test test/eval.test.js`。APIキーは不要です。作業フォルダ・隔離 HOME・子プロセスは実行終了時に片付けます。
