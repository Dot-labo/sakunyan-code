# sakunyan のくわしい説明

入れ方と、よくあるつまずきは [README](../README.md) にあります。ここには、それ以外のくわしい説明をまとめています。

## できること

- ファイルやコードの読み取り・調査
- エラーの原因説明と解決方法の案内
- Gitの状態やコマンドの実行結果を一緒に読み解く
- コマンドの意味を説明してから、実行方法を案内

アドバイスモードとチューターモードのどちらでも、`read`、`grep`、`find`、`ls` によるファイルの読み取り・検索・一覧表示と、[記憶](#記憶について)の読み書きだけを自動で行います。`bash`、`edit`、`write` は使いません。Gitの状態確認を含むコマンドの実行やファイルの変更が必要なときは、手順を説明し、利用者自身に実行してもらいます。出力やエラーを貼り付ければ、その内容を一緒に確認できます。

起動時にプロジェクトの `AGENTS.md` や `CLAUDE.md`、拡張機能、Skills、プロンプトテンプレートを自動読み込みしません。[教室共通のルール](#教室共通のルールツールライブラリの方針)は、パソコンのファイルからではなく、sakunyanの中に入っている固定の内容を使います。読み取りツールはOSのサンドボックスではなく、起動フォルダ外の読み取りを完全に防ぐ仕組みではありません。APIキーや個人情報を含むファイルは、sakunyanに読み取らせたり、会話へ貼り付けたりしないでください。

## 作業フォルダの指定

フォルダごとの設定は使いません。作業フォルダや親フォルダの `.pi/`、`.agents/skills`、プロジェクト内の `.sakunyan/` があっても、そこにある設定・パッケージ・指示は読み込みません。pi の信頼確認の文は表示せず、`/trust` も使いません。以前に保存した信頼の決定があっても、この方針は変わりません。利用者の設定は、これまでどおり `~/.sakunyan/settings.json` に保存します。

`sakunyan` の後ろに、作業したいフォルダを書きます。今いるフォルダなら `.` です。

```sh
sakunyan .
sakunyan ~/projects/my-project
sakunyan "./my project"
```

WindowsのGit Bashでは、例として次のように指定します。

```sh
sakunyan /c/Users/名前/projects/my-project
```

インストールせずに一度だけ実行する場合は、次の方法も使えます。

```sh
npx @dotlabo/sakunyan-code@latest .
```

起動時は「さくにゃんを起動中…」「設定と画面を準備中…」の順に表示され、画面が開くときに消えます。画面が開いた後に接続確認が始まります。待ち時間の測定結果は[起動とインストールの待ち時間](performance.md)にあります。

## オプション

```text
sakunyan [オプション] <作業フォルダのパス>
```

| オプション | 説明 |
| --- | --- |
| `-v`, `--version` | sakunyanのバージョン（例: `0.1.19`）を表示して終了します |
| `-h`, `--help` | 使い方、作業フォルダの指定例、オプションの一覧を表示して終了します |
| `--` | これより後ろをオプションとして扱いません |

```sh
sakunyan --version
sakunyan --help
```

- `--version` と `--help` は、作業フォルダを指定しなくても、どの位置に書いても使えます。フォルダの確認、対話画面の起動、ネットワーク接続、APIキーの入力は行いません。
- `-` で始まる名前のフォルダで作業する場合は、`--` の後ろに書きます。

  ```sh
  sakunyan -- --my-project
  ```

- 上の表にないオプションを作業フォルダより前に書くと、エラーと `sakunyan --help` の案内を表示して終了します（終了コード 2）。作業フォルダを指定しなかった場合は、フォルダの指定方法を案内して終了します（終了コード 1）。
- 作業フォルダより後ろに書いた引数は、pi の SDK を使う sakunyan の固定ランタイムで解釈します（`-v`、`--version`、`-h`、`--help` を除く。`--` より後ろでは内部ランタイムの案内になります）。`--print`、`--mode`、`--offline`、`--no-session` などを使えます。モデルとツールは固定し、`--approve`、拡張・Skills・プロンプト・テーマ・システム指示ファイルの指定を渡しても、プロジェクト由来の入力は有効になりません。ふだんの利用では指定する必要はありません。

## APIキーとモデル

初回起動時に、sakunyanがOpenRouterの固定モデルへ接続できない場合、APIキーの入力画面が表示されます。

接続に成功すると、APIキーはsakunyan専用の保存先へ保存され、次回から再入力せずに使えます。APIキーはログやエラーメッセージには表示されません。

接続できないときは、AIのサーバーまで通信が届くかどうかを確かめます（APIキーは送りません）。届かないときは、APIキーの案内のかわりに、インターネットの確認を案内します。

使用するプロバイダとモデルは sakunyan 側で固定されています。

```text
プロバイダ: openrouter
モデル: deepseek/deepseek-v4-flash
```

APIキーは他の人に見せたり、GitHubへ公開したりしないでください。

## 保存先について

sakunyanは、pi本体とは別のsakunyan専用フォルダに認証情報・設定・対話履歴を保存します。

```text
~/.sakunyan/
├── auth.json      APIキーなどの認証情報
├── settings.json  sakunyanの設定
├── sessions/      対話履歴・セッション
└── memory/        記憶（pi-memory）
```

pi本体の保存先(`~/.pi/`)は変更・削除しません。piとsakunyanで、認証情報・設定・対話履歴はそれぞれ独立しているため、片方の会話や設定変更がもう片方に影響することはありません。

### 記憶について

sakunyanは、pi の拡張機能 [pi-memory](https://github.com/jayzeng/pi-memory) で、セッションをまたいで覚えておくことを保存します。覚え方や使い方は pi-memory のとおりです。保存先だけを、pi-memory の既定（`~/.pi/agent/memory/`）から `~/.sakunyan/memory/` に変えています。中身はふつうの Markdown ファイルなので、開いて確認・修正できます。フォルダごと削除すると、記憶はすべて消えます。

### 初回起動時について

以前のバージョンのsakunyanが`~/.pi/agent/`に保存していたAPIキーや対話履歴は、pi本体のものと区別できないため、自動では引き継ぎません。初回起動時にAPIキーを再入力してください。

## 起動後の表示

```text
sakunyan code (バージョン)へようこそ！
作業フォルダ： 📁 現在のフォルダ
ユーザーの環境： 🍎 macOS

💡 ヒント：「/resume」と入力すると、前の会話を選んで続きから再開できるよ。
🐱 質問を入力してね（Ctrl+Cを2回で終了）
```

初めての人が迷わないように、APIキーの設定が済むまでは、ロゴ・作業フォルダとAPIキーの設定の案内だけを出します。ヒント、新しいバージョンのお知らせ、画面の下の行（作業フォルダの場所・会話の量・入力の案内）は、APIキーの設定が済んでから出します。保存したAPIキーがあるときは、はじめから出し、そのキーで接続できなかったときは、APIキーを入れ直すまで隠します。

- ホームのフォルダで起動したときは、作業フォルダの行の下に「🏠 ホームのフォルダで起動したよ。作業用のフォルダを作って、そこで起動すると安心だよ。」と出します。
- 画面の下の「💬 会話の量 3.2%/1.0M」は、会話が始まってから出します。1回の会話で AI が覚えておける量（コンテキスト）のうち、どれだけ使ったかです。70% をこえると黄色、90% をこえると赤で出します。

質問は短く、分からないことをそのまま入力してください。sakunyanが、子どもにも分かる言葉で説明します。

### 応答モード（答え方）

`/mode` と入力すると、答え方を選べます。上下の矢印キーで選び、Enterで決めます（Escでやめます）。いまのモードの名前は、画面の下の行に出ます。

| モード | 答え方 |
| --- | --- |
| アドバイスモード（既定） | 一緒に調べながら、考え方や手順を分かりやすく説明します。必要に応じて、コマンドや変更例も示します。 |
| チューターモード | 自分で考えて作れるように、ヒントを少しずつ出します。すぐに答えを出さないことがあります。 |

チューターモードでは、次のように答えます。

- タイプミスや、インストール・パス・道具の使い方のつまずきは、すぐに場所と直し方を教えます。
- いま学んでいることは、手がかりを4段で少しずつ出します（問い返しや次の小さな一歩 → 考え方と、題材のちがう短い例 → 課題のコードの穴埋め → 答えと行ごとの説明）。同じ所でつまずいたら、1段進みます。
- 行きづまっているとき、時間が無いとき、自分で試したうえで答えを求めたときは、早めに答えを示します。
- プログラムが動いたときと、答えを見せたあとに、理解を1問で確かめることがあります。

どちらのモードでも、使うのは読み取りのツール（`read`、`grep`、`find`、`ls`）と[記憶](#記憶について)のツールだけです。作業フォルダのファイルの変更やコマンドの実行は行いません。選んだモードは保存しません。起動したとき、`/new` で新しい会話を始めたときは、アドバイスモードにもどります。画面のない実行（`-p` など）では、いつもアドバイスモードです。

モードの定義（名前、説明、指示文、使えるツール）は [`src/modes.ts`](../src/modes.ts) にまとめています。

### 起動時のヒント

起動するたびに、ヒントを1件、ランダムに選んで表示します（「💡 ヒント：…」の行）。表示するのは起動したときの1回だけで、`/new` や `/resume` のあとには出しません。ゲームのロード画面のtipsのように、起動後の接続確認を待つ間に読めます（APIキーがまだ無いときは、設定が済んでから出します）。内容は次の2種類です。

- 使い方のヒント：sakunyanのコマンド（`/resume`、`/mode` など）、APIキーの発行、入力欄の使い方（`!` でコマンド実行、`@` でファイル名の候補など）、ショートカットキー、ターミナルの基本コマンド（`ls`、`cd`、`git`、`gh` など）、パソコン一般のショートカット（全選択、コピーと貼り付けなど。WindowsなどはCtrl、macOSはCommandで出し分けます）
- 豆知識：コンピュータの仕組み、ネットワーク、歴史、プログラミング言語について、1〜2文で読めるもの

PowerShellのように環境によって違う内容は、判定した環境に合うときだけ表示します。ヒントは画面に表示するだけで、AIへの指示や入力した質問には含めません。

ヒントの一覧は [`src/tips.ts`](../src/tips.ts) の `SAKUNYAN_TIPS` にまとめています。追加・修正・削除は、この一覧だけを編集します。

```ts
{ text: "どの環境でも表示するヒント" },
{ os: ["Windows"], text: "Windowsのときだけ表示するヒント" },
```

`os` には `"Windows"`、`"macOS"`、`"Chromebook"`、`"Linux"` を指定できます。実際に使えるコマンド・キー操作だけを書いてください。ターミナルやsakunyanの中では意味が違うキー（Ctrl+C、Ctrl+Aなど）は、どこで使えるかを文に書いてください。豆知識は、確かな事実だけを、待ち時間に読み切れる長さ（1〜2文）で書いてください。件数が増えると1件あたりの出る回数が減るので、ひとつの環境で候補になる数は50件くらいを目安にしてください。一覧を空にしても、ヒントの行が出なくなるだけで、起動と会話はそのまま使えます。

sakunyanは起動した環境を判定し、そのOSに合わせてコマンドや操作手順を案内します。ChromebookではLinux開発環境を使う前提です。ChromeOS固有の情報がLinux環境から見えない場合はLinuxとして判定します。OSを判定できない場合はWindowsとして案内します。別のPCやサーバーについて質問するときは、その環境を伝えてください。

## 教室共通のルール（ツール・ライブラリの方針）

教室で主に使うツールやライブラリの方針は、sakunyanの中に入っています（固定の内容）。sakunyanはその内容をAIへの指示に加え、どの応答モードでも、関係する質問への案内に反映します。

```md
# 教室共通のルール（ツール・ライブラリの方針）

- Pythonのパッケージ管理は、基本的に `uv` を案内する
- GitHubのリポジトリ操作やアカウント認証は、基本的に `gh` コマンドを案内する
- Pythonで簡単なゲームを作る場合は、`pyxel` を候補にする
```

- 利用者のパソコンには、ルールのファイルを作りません。パソコンのファイルを読み込むこともありません。作業フォルダの中のファイル（`CLASSROOM.md`、`AGENTS.md`、`CLAUDE.md` など）も読み込みません。
- ルールは、どのパソコンでも同じです。パソコンごとに変えることはできません。
- 内容は [`src/classroom-rules.ts`](../src/classroom-rules.ts) の `CLASSROOM_RULES` にあります。変えるときは、ここを直して新しいバージョンを公開します。それぞれのパソコンでは、sakunyanを[更新](#更新について)すると新しい内容になります。

### 優先順位

- ルールは「教室の既定の選択肢」です。利用者が別のツールや方法を明示した場合や、課題・環境の制約がある場合は、そちらを優先して答えるよう、AIに指示しています。
- ルールによって、使えるツール（`read`、`grep`、`find`、`ls`）や、応答モードの制限（ファイルを変更しない、コマンドを実行しないなど）は変わりません。

### 0.1.16を使っていた場合

0.1.16だけは、ルールを `~/.sakunyan/CLASSROOM.md`（Windowsでは `C:\Users\名前\.sakunyan\CLASSROOM.md`）というファイルに作り、そこから読み込んでいました。0.1.17からは、このファイルを使いません。

- ファイルが残っていても、中身はAIへの指示に入りません。手で直した内容も、反映されなくなります。
- sakunyanは、残っているファイルを書き換えたり消したりしません。不要なら、手で削除してかまいません。
- 更新したときに、画面での知らせは出ません。手で直した方針を続けて使いたい場合は、運営者に伝えて、sakunyanの中のルールに入れてもらってください。

## 更新について

新しいバージョンが公開されている場合は、起動時に画面へ1行の案内が表示されます（APIキーの設定が済んでから）。更新のコマンドは [README の「更新のしかた」](../README.md#更新のしかた)にあります。Windowsでは、案内に出るコマンドは `npm.cmd install -g …` になります（PowerShellの実行ポリシーで止まらないようにするため）。

更新しても、保存先のAPIキーや対話履歴はそのまま使えます。[教室共通のルール](#教室共通のルールツールライブラリの方針)は、更新すると新しいバージョンの内容になります。

## 開発する人へ

必要なものは Node.js 22.19.0 以上です。

```sh
npm ci
npm run typecheck
npm test
```

- `npm test` は、ビルド（`tsc`）のあとにテスト（`node --test`）を実行します。作業フォルダの名前は任意です。プロジェクト入力と信頼の検証方法は [issue #35 の調査記録](project-inputs.md) にあります。
- 手元でビルドしたものを、公開されているものと同じ形で試すには、`npm pack` で作った `.tgz` を `npm install -g <tgzのパス>` で入れます。
- 画面に出す文は [`src/messages.ts`](../src/messages.ts) にまとめています。
- 仕様は [`openspec/specs/`](../openspec/specs/) にあります。

### Windows の Git Bash について

入力欄で `!` を使ってコマンドを動かす機能は、Windows では Git for Windows（Git Bash）の `bash.exe` を使います。sakunyanが内部で使っているpiが `bash.exe` を探すのは、コマンドを動かすときです。Git Bash が入っていない Windows での動作は、まだ実機で確かめていません。
