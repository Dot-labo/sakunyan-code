# 起動とインストールの待ち時間

## 2026-09-29 の測定

環境は macOS arm64、Node.js v24.13.0、npm 11.6.2。起動は新しい一時ホームディレクトリを使い、PTY で `sakunyan .` を実行した。APIキーは設定していないため、質問可能になるまでの時間は測定対象外。

| 操作 | 最初の表示 | 画面表示または終了 |
| --- | ---: | ---: |
| 変更前の起動 | 約 0.81 秒 | 最初の TUI 描画も約 0.81 秒 |
| 変更後の起動 | 約 0.04 秒 | TUI 描画は約 0.53 秒 |
| ローカル tarball の新規グローバルインストール | 約 4.85 秒 | 約 6.09 秒 |
| 同じ tarball での更新 | 約 1.87 秒 | 約 5.76 秒 |
| グローバルインストール直後の初回起動 | 約 0.93 秒 | TUI 約 2.31 秒、APIキー入力 約 2.45 秒 |
| グローバル更新直後の初回起動 | 約 0.45 秒 | TUI 約 1.71 秒、APIキー入力 約 1.87 秒 |

インストールと更新は `npm pack` で作ったローカル tarball を一時 prefix に `npm install -g` し、標準の npm 出力を測定した。続けてその prefix の `sakunyan` を一時ホームディレクトリで起動した。公開レジストリからの取得時間は含まない。macOS では10秒超の無表示は再現しなかった。Windows、遅いネットワーク、APIキーを設定済みの環境では未測定。

## 待機する場所

- 変更前は `src/cli.ts` の静的 import が pi 本体と拡張機能を読み込むため、最初の表示はその読み込みと pi の初期化が終わった後だった。変更後は重い import の前に「起動中」、pi の初期化前に「設定と画面を準備中」を表示する。
- TUI が出た後のモデル接続確認には最大15秒のタイムアウトがあり、その間は画面にスピナーを表示する。失敗するとAPIキー入力画面へ進む。
- npm の更新確認は最大5秒、キーの状態確認は最大10秒だが、どちらも起動画面の後に非同期で実行する。初回描画を待たせない。
- `package.json` にあった sakunyan 自身への依存は不要で、npm が旧版を追加で取得・展開する原因だったため削除した。
- npm のインストール・更新中は sakunyan 自体がまだ動いていない。表示されない時間は npm の取得、依存解決、展開やネットワーク環境に依存する。

起動に10秒以上かかる環境では、最初の「起動中」と次の「設定と画面を準備中」のどちらで長く待つかを記録すると、パッケージ読み込みと pi の初期化を切り分けられる。
